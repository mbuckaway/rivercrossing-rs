RiverCrossing User Guide

RiverCrossing records a poker-run ride: it registers riders and teams, records plate crossings, deals and tracks cards, and produces standings, exports and a published results page.

1. Getting started

RiverCrossing opens on the live timing console. With no ride loaded the console is empty, the clocks read zero and the plate field is locked.

If a ride was still running when the app last closed, a Resume Ride prompt appears at launch. Continue reloads that ride; Ride Library (or Escape) opens the ride library instead.

Create a ride

  1. Choose File ▸ New Ride…. New Ride is available only while no ride is loaded.
  2. Complete the Ride Setup form and confirm with OK. The ride is saved as a draft.
  3. Add riders or teams from the Riders menu, then choose Ride ▸ Start Ride.

Everyday housekeeping

  • File ▸ Back Up Database… writes a timestamped backup. The app also checks for an hourly backup while it runs.
  • File ▸ Ride Library lists the saved rides so you can open, duplicate or delete one. Deleting a ride requires typing its exact name.
  • File ▸ Exit quits. While a ride is running the app first asks whether to keep it running, finish it first, or cancel.
  • On macOS the window's close button hides the console; the app keeps running. Click the Dock icon to restore it, and quit from File ▸ Exit.

This guide is always available from Help ▸ User Guide.

2. The console

The console is the main window. It shows the ride identity and status, the two race clocks, the entry row, the crossings feed and the review panel.

The status and clocks

The status word is DRAFT, RUNNING, STOPPED, FINISHED or REOPENED, matched by a status light. The elapsed and remaining clocks advance only while the ride is live and freeze when it is stopped or finished.

The entry row

The entry row holds the large Plate field, the Record and Undo buttons, and a line naming the last recorded crossing. The plate field and Record are enabled only while the ride is live; Undo is enabled once there is at least one crossing.

The crossings feed and review panel

The crossings feed lists every recorded crossing for the whole ride, with the card each rider drew. The search box filters the feed by plate, name or card. Beside the feed, the review panel has two tabs:

  • Riders — the live roster.
  • Needs Review — crossings flagged for a second look, with a show held only filter and a review button.

The status bar carries count chips (crossings, cards, on course, shoe, riders, and teams when the ride has teams).

The tool rail

The tool rail is a shortcut surface for the same actions as the menus: Ride Library, Rider Editor, Teams Editor, Check for Rider Issues, Standings, Audit Trail and Settings.

3. Ride setup

File ▸ New Ride… opens a blank form; Ride ▸ Edit Ride… opens the same form preloaded with the open ride. OK saves and closes; Cancel discards; invalid input is reported at the top of the form and the dialog stays open.

Event identity

Name, event date, start time, venue, organizer, scorer, lap length in kilometres, ride duration and minimum lap time. These fields stay editable for the life of the ride.

Format

  • Entry mode: solo or mixed (solo riders and teams).
  • Team size, from 2 to 10.
  • Plate model: plates pooled across the ride, or relay plates per team.
  • Decks and jokers per deck, and whether jokers count per deck or as a ride total.
  • Optional cap on the cards a rider may draw.
  • Tie-break order, which decides how equal results are ranked.

Short-lap policy

The ride chooses whether a lap shorter than the minimum holds the rider short or still deals a card. The minimum lap time is set in the event identity fields.

Logo

The logo column previews the organizer logo and offers a browse button. The chosen logo appears in the export header and on the published page.

Locking

Once the ride leaves draft, structural fields lock: the entry-mode and plate-model choices lock for relay rides, and decks, jokers, cap and tie-break lock for every ride. The event identity stays editable.

4. Riders and teams

Rider Editor

Riders ▸ Rider Editor lists the roster with a search box and a read-only record panel. Use Add, Edit and Delete; Delete is offered only when the ride's state and data allow it. The team column is hidden on a solo ride.

The Add/Edit Rider form carries plate, first name, last name, team and sex. The plate is locked once the ride leaves draft.

Teams Editor

Riders ▸ Teams Editor is available on a mixed ride. It lists the teams, their relay plate and their members, with Add, Edit and Remove. A team may be restricted to a single member; the relay plate row appears only on a relay ride. Team edits are available while the ride is in draft.

Check for Rider Issues

Riders ▸ Check for Rider Issues… reports roster problems such as a team of one, a missing plate or a duplicate plate. Each issue row offers the fix it can apply: open the rider editor, convert to solo, assign a plate, or renumber. Plate fixes are available in draft.

Import and export the roster

In this release the Import Riders CSV… and Export Riders CSV… entries report that a file picker is not available; the CSV preview and commit follow in a later release.

When the picker is available, Import opens a preview that lists conflicts and refuses to import while any remain. Two options map an unknown sex value and convert teams of one.

5. Recording crossings

  1. Start the ride with Ride ▸ Start Ride. If the ride cannot start, the Cannot Start Ride dialog lists the reasons; fix the setup or roster and start again.
  2. Type a plate into the Plate field and press Enter, or click Record.
  3. The crossing joins the feed, the last-crossing line names it, and the count chips update.

The entry field stays locked unless the ride is live. A rider who is on course or has finished, or a plate that is not on the roster, is reported and the crossing is not recorded.

The View menu adds the total-time and lap-time columns to the crossings panel. Cards ▸ Undo Last Crossing (Ctrl+Z) removes the most recent crossing after a confirmation.

6. Corrections and voids

Crossing Detail

Opening a row in the crossings feed shows the crossing's rider, team, plate, lap, time, lap time, total, card and held status. From there:

  • Edit retypes the plate.
  • Edit Time… corrects the crossing time.
  • Void Card… voids the card a rider drew; a reason is required.
  • Delete… removes the crossing after a confirmation.

Add and deal

Cards ▸ Add Crossing at Time… records a crossing with a time you type. Cards ▸ Deal Bonus Card… deals a bonus card to a plate, with a reason.

Audit Trail

Ride ▸ Audit Trail… is a read-only record of every action on the ride, with the time, action, entry and reason. It has a search box and an action filter. The entry is available once the ride has at least one audit row.

Every correction is written to the audit trail, so a voided or deleted crossing leaves a record even after it leaves the feed.

7. Cards and DNF

Cards are dealt from the ride's shoe as crossings are recorded. The ride setup fixes the number of decks, the jokers, the cap and the short-lap policy, and the Views and Results menus decide which card details appear in the feed and in the exports.

Held and voided cards

A card can be held instead of credited, for example after a short lap. The Needs Review tab routes held cards to their decision, and a credited card can be voided from Crossing Detail with a reason.

Deal a card by hand

Cards ▸ Deal Bonus Card… asks for a plate and a reason; its confirm button reads Deal.

Mark DNF

Riders ▸ Mark DNF… asks for a plate and a reason, and records that the rider did not finish. Cancel is the default button, so a stray Enter does not mark anyone. Riders who did not start can be shown or hidden on a finished ride's results with Results ▸ Show DNS Riders.

8. Stopping, finishing and reopening

Stop

Ride ▸ Stop Ride… asks for a confirmation and stops the clocks. A stopped ride is not finished: Start Ride continues it, and the setup and roster can still be corrected.

Finish

Ride ▸ Finish Ride… asks for a destructive confirmation and locks the ride for results. Exports, previews and publishing become available only on a finished ride. Finishing is the point after which the results are final.

Reopen

Ride ▸ Reopen Ride asks for a confirmation and reopens a finished ride for corrections. Reopening returns the ride to the correction state; finish it again when the corrections are done.

Clear

Ride ▸ Clear Ride… asks for a destructive confirmation and unloads the ride from the console. Clearing does not delete the ride from the library.

Quit while a ride is running

Exit while a ride is live opens the Ride Is Running dialog: cancel, finish the ride first, or quit and let the ride keep running. A ride left running is offered for resumption at the next launch.

9. Standings and results

Results ▸ Standings (F5) opens the standings window. It is available at every ride state: it is empty with no ride, live while the ride runs, and final once the ride is finished. A stale marker appears when the ride changes after the window was built; close and reopen Standings to see the new ranking.

On a mixed ride the window has separate Teams and Solo tables; a solo ride shows one table. Rows rank by the ride's tie-break order, and a card cell marks the cards each rider drew.

Results options

The Results menu carries the options that shape exports and the published page:

  • Show lap & total times — adds the timing columns.
  • Laps leaderboard — adds the laps ranking.
  • Fastest-time leaderboard — adds the fastest-time ranking; available only while Show lap & total times is on.
  • Full field — lists the whole field.
  • All cards drawn — shows every card a rider drew.
  • Show DNS Riders — includes riders who did not start.

10. Exports and publishing

Exports are available on a finished ride. Each export opens a save picker and writes in the background; the file's path is recorded so it can be previewed.

Results menu entryWhat it writes
Export HTML…The results page as a self-contained HTML file.
Export PDF…The results report as a PDF.
Podium Poster PDF…The podium poster as a PDF.
Podium Poster HTML…The podium poster as an HTML page.
Export Standings CSV…The standings as a CSV file.

Preview

Preview HTML in Browser, Preview Podium Poster HTML in Browser and Preview PDF in Browser open the file written this session. If the export has not been written yet, the app says Export the file first.

Publish to WordPress

  1. Choose Results ▸ Publish to WordPress….
  2. Choose the kind, Full results or Podium; changing the kind refills the title and slug.
  3. Enter the site URL and credentials, and the page title, slug, optional parent page and status (Draft, Publish, Pending or Private).
  4. Confirm with Publish. A blank or non-https URL keeps the form open with the reason.

The Publishing to WordPress window shows progress and a Cancel button; cancelling abandons the publish at its next checkpoint. On success the app offers to open the published page; on failure it offers Retry.

11. Settings and appearance

File ▸ Settings… opens the app-wide settings. OK saves them and Cancel discards the changes.

Appearance

  • Theme — one picker listing each built-in theme's Light, Dark and System variants.
  • Contrast — System, Standard or High.
  • Density — Compact or Comfortable.
  • Text size — Tiny, Small, Medium or Large.

The View menu repeats Density and Text size as quick choices, and carries the two console column options: Show Total Times on Crossings Panel and Show Lap Time on Crossings Panel.

Other settings

  • Sound — plays the console's cues.
  • Show total times and Show lap time — the console columns.
  • Verbose log — writes more detail to the launch log.
  • Average rider speed — the default the simulator uses to propose a crossing interval.

Settings are stored beside the ride database in the per-user configuration directory, in the same format as the earlier Python version of RiverCrossing.

Appendix B — Troubleshooting

The ride will not start

The Cannot Start Ride dialog lists the reasons. Start needs a complete setup and a roster, and is available only on a draft, stopped or reopened ride. Fix the reason in Ride Setup or the Rider Editor and start again.

The plate field will not accept input

Entry is enabled only while the ride is live. Start the ride, and resume it if it was stopped.

Import or export of the roster reports a missing file picker

That notice is expected in this release: the roster CSV save and open pickers are not yet available. The results exports use the same picker and are available on a finished ride.

Exports and previews are disabled

Exports need a finished ride, and each preview needs its export written this session. Finish the ride, export the file, then preview it. A preview with no export says Export the file first.

The publish fails

Check that the site URL is https and the credentials are correct, then choose Retry in the failure box. A cancelled publish never changes the site.

Standings look out of date

The stale marker means the ride changed after the standings window was built. Close and reopen Standings.

The User Guide does not open

The guide is written to the per-user configuration directory and then opened in your browser. If either step fails, the status bar names the failure; check that the configuration directory is writable and that a default browser is set.

The window disappeared on macOS

The close button hides the console; the app keeps running. Click the Dock icon to bring it back, and quit only from File ▸ Exit.
